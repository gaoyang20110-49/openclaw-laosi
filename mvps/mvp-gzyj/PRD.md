## 一、产品概述

### 1.1 产品定位

一款面向IDC暖通技术专家的**旁通阀异动预警工具**，通过采集阀门开度反馈值（PV），基于用户自定义规则，在旁通阀发生异常开启行为时第一时间触发系统内预警，将故障发现时间从 >30分钟压缩至 ≤5分钟。

### 1.2 核心价值

> 在温度/压力超限**之前**，从阀门行为层捕捉异动信号，实现主动预警。

### 1.3 MVP功能边界

**In Scope（本期实现）：**
- 阀门数据导入（Excel / 飞书表格）+ 前端导入入口与数据查看
- 阀门重要性标记（导入批量标记 + 页面手动标记）
- 实时监控看板（机房切换 + PV 展示）
- 预警规则配置（场景A/B + 机房×阀门类型前置判断 + 参数自定义 + 规则删除约束）
- 预警触发与系统内通知（含事件归并 + 恢复通知）
- 预警中心（事件视图 + 告警记录双Tab + 事件详情）
- 历史数据查询与曲线回溯
- 调试时间模式（实时/调试双模式切换）

**Out of Scope（本期不做）：**
- 执行器响应异常等其他预警场景
- 预警等级区分（警告/高危）
- 外部通知推送（邮件/企微/短信）
- 用户账号与权限体系
- DCOM API直连（长期规划）
- 控制指令值 SP 采集与展示
- 控制器状态字段
- 数据存储时间策略（MVP不做深入规划）

## 三、数据规格

### 3.1 时序数据字段定义

| 字段名 | 中文名 | 类型 | 必填 | 说明 | 示例 |
|--------|--------|------|------|------|------|
| `timestamp` | 采集时间 | datetime | ✅ | 数据采集时间戳，规则引擎时间轴基准 | 2025-11-28 14:30:00 |
| `site_code` | 机房编号 | string | ✅ | 机房唯一标识编号 | IDC-BJ-01 |
| `valve_id` | 阀门编号 | string | ✅ | 阀门唯一编号（同机房内唯一） | V10a |
| `valve_type` | 阀门类型 | string | ✅ | 阀门类型描述 | 冷冻侧主管网旁通阀 |
| `point_name` | 测点名称 | string | ✅ | 该阀门在DCOM中的测点名称 | 冷冻侧旁通阀V10a开度反馈 |
| `point_id` | 测点ID | string | ✅ | DCOM系统固定字段，格式规范待补充 | PT-V10A-PV-001 |
| `pv_value` | 开度反馈值 | float | ✅ | 阀门实际开度 PV（0-100%），超出范围拒绝导入 | 23.5 |
| `is_important` | 是否重要阀门 | boolean | ❌ | 标记该阀门是否为重要阀门；为空时不覆盖现有标记 | true / false |
| `data_source` | 数据来源 | string | ❌ | 导入来源标识，系统自动填充 | excel_import |

> **时间轴说明**：规则引擎所有窗口计算均使用 `timestamp`（采集时间），不使用数据入库时间。

### 3.2 阀门档案字段定义

| 字段名 | 中文名 | 类型 | 说明 |
|--------|--------|------|------|
| `valve_id` | 阀门编号 | string | 与 site_code 联合唯一，同机房内不重复 |
| `site_code` | 所属机房 | string | 关联机房编号 |
| `valve_type` | 阀门类型 | string | 类型描述 |

| `is_important` | 是否重要阀门 | boolean | **唯一数据来源**；默认 false；可通过导入或页面手动修改 |
| `created_at` | 创建时间 | datetime | 系统自动填充 |

> **重要性字段唯一来源（SSOT）**：`is_important` 以阀门档案为准，时序数据中的 `is_important` 列仅用于触发档案更新，规则引擎读取时始终从阀门档案取值。

### 3.4 Excel 导入格式规范

- 文件格式：`.xlsx` / `.csv`
- 表头行：第1行为字段名（与3.1字段名一致）
- 时间格式：`YYYY-MM-DD HH:MM:SS`
- 数值格式：小数点格式，如 `23.5`（非百分号格式）；超出 0~100 范围的行拒绝导入
- `is_important` 填写规范：`true` / `false` 或 `1` / `0`，大小写不敏感；为空则不覆盖现有标记
- **单次导入上限：5万行**
- 系统提供**导入模板下载**功能（模板含 `is_important` 列及填写说明）

### 3.5 数据存储策略

| 项目 | 规则 |
|------|------|
| 存储容量上限 | **1 GB**（PostgreSQL数据库总量，MVP固定上限） |
| 时间限制 | 无（不按时间清理） |
| 达到上限处理 | 前端提示存储空间不足，阻止新导入，引导用户手动清理 |
| 清理方式 | 用户在「历史数据」页面按时间范围手动删除 |
| 预警阈值 | 使用量超过 **800MB（80%）** 时，页面顶部展示存储预警提示 |

### 4.3 模块三：预警规则配置

#### 4.3.1 功能描述

用户可自定义预警规则，两种场景均支持通过「机房 + 阀门类型」前置条件缩小生效范围，所有参数填写完整后规则才可保存生效。规则存在关联活跃事件时不可删除。

#### 4.3.2 规则触发完整逻辑（场景A / B 统一）

```
Step 1：机房匹配
该阀门所属机房 ∈ 规则配置的适用机房？
（全部机房 → 直接通过；指定机房 → 需匹配）
 ↓ 通过
Step 2：阀门类型匹配
┌──────────────┬──────────────────────────┐
│ 规则配置选项 │ 生效条件 │
├──────────────┼──────────────────────────┤
│ 仅重要阀门 │ is_important = true │
│ 仅非重要阀门 │ is_important = false │
│ 全部阀门 │ 不限 │
└──────────────┴──────────────────────────┘
 ↓ 通过
Step 3：触发公式计算（见各场景定义）
 ↓ 满足
Step 4：事件归并判断
→ 存在 active incident（同规则+同机房+同阀门）→ 追加持续日志
→ 不存在 active incident → 创建新事件，产生触发通知
```

#### 4.3.3 场景参数定义

##### 场景A：持续高位预警

> **适用场景**：阀门开度持续处于高位，反映系统存在持续异常。

**触发条件（满足任一即触发）**：

```
条件1（点数）：在时间窗口内，存在连续 n_points 个点的 pv_value ≥ threshold
条件2（时长）：在时间窗口内，存在连续若干点的 pv_value ≥ threshold，
 且这些点的时间跨度 ≥ n_minutes 分钟

→ 条件1 OR 条件2，满足任一即触发
```

**参数说明**：

| 参数 | 说明 | 默认值 | 生效条件 |
|------|------|--------|---------|
| 触发点数 `n_points` | 连续满足阈值的采集点数 | **空** | 必填，为空时无法保存 |
| 触发时长 `n_minutes` | 连续满足阈值的时间跨度（分钟） | **空** | 必填，为空时无法保存 |
| PV阈值 `threshold` | 开度超过此值视为高位（0~100%） | **空** | 必填，为空时无法保存 |
| 恢复点数 `recover_points` | 连续低于阈值的点数，满足后事件恢复 | 2 | 可选，默认2 |
| 恢复时长 `recover_minutes` | 连续低于阈值的时间跨度（分钟） | 2 | 可选，默认2 |

> **恢复条件（同样满足任一即恢复）**：
> - 连续 `recover_points` 个点 pv_value < threshold
> - 连续若干点 pv_value < threshold 且时间跨度 ≥ `recover_minutes` 分钟

##### 场景B：短时间内剧烈波动

> **适用场景**：阀门在短时间内开度大幅变化，反映系统出现异常扰动。

**触发条件**：

```
在时间窗口 [now - window_minutes, now] 内，
取所有 pv_value 不为 NULL 的点（允许非连续，跨断点参与计算），
计算：max(pv_value) - min(pv_value) ≥ delta_threshold
```

**参数说明**：

| 参数 | 说明 | 默认值 | 生效条件 |
|------|------|--------|---------|
| 时间窗口 `window_minutes` | 计算窗口时长（分钟） | **空** | 必填，为空时无法保存 |
| 波动阈值 `delta_threshold` | 窗口内 max-min 超过此值触发（%） | **空** | 必填，为空时无法保存 |
| 恢复阈值 `recover_delta_threshold` | 窗口内 max-min 低于此值时事件恢复（建议设为触发阈值×0.8） | 自动计算 | 可选，默认为触发阈值×0.8 |

> **跨断点说明**：窗口内即使存在数据缺失（断点），非连续的采集点仍全部参与 max/min 计算，不要求数据连续。

#### 4.3.4 规则通用配置项

| 参数 | 说明 | 配置方式 |
|------|------|---------|
| 规则名称 | 自定义规则标识 | 文本输入（必填） |
| 预警场景 | 选择场景A 或 场景B | 单选（必选） |
| 适用机房 | 绑定到特定机房，或选择"全部机房" | 下拉单选 |
| 适用阀门类型 | 仅重要阀门 / 仅非重要阀门 / 全部阀门 | 单选（必选） |
| 规则状态 | 启用 / 停用 | 开关（默认启用） |

#### 4.3.5 规则删除约束

| 场景 | 行为 |
|------|------|
| 规则无关联活跃事件 | 允许删除，删除后规则及其历史告警记录均保留（软删除标记） |
| 规则存在 active 事件 | **拒绝删除**，提示「该规则存在 X 个活跃预警事件，请先关闭或等待事件恢复后再删除」 |

### 4.6 模块六：调试时间模式（v1.5 新增）

#### 4.6.1 功能描述

系统支持**实时模式**与**调试模式**两种时间模式，供开发测试与历史数据回溯验证使用。调试模式下，规则引擎以用户指定的历史时间点作为「当前时间」进行计算，不影响生产告警数据。

#### 4.6.2 入口位置

- **位置**：全局 TopBar 右侧，预警铃铛左侧
- **实时模式显示**：🟢 绿色圆点 + `实时模式`
- **调试模式显示**：🟡 黄色圆点 + `调试模式：2025-11-28 14:35:00`

#### 4.6.3 操作方式

```
点击 TopBar 时间模式标识
 ↓
弹出模态框
┌──────────────────────────────────┐
│ 时间模式设置 │
│ ⦿ 实时模式（使用当前时间） │
│ ○ 调试模式（指定历史时间点） │
│ │
│ 调试时间：[2025-11-28 14:35:00] │
│ （不可设置未来时间） │
│ [取消] [确认] │
└──────────────────────────────────┘
```

#### 4.6.4 模式约束

| 约束项 | 说明 |
|--------|------|
| 调试时间格式 | 必须为 `YYYY-MM-DD HH:MM:SS` |
| 调试时间范围 | 不得晚于当前真实时间（不允许设置未来时间） |
| 规则引擎行为 | 调试模式下仍按正常频率运行，但窗口计算基于调试时间点 |
| 数据隔离 | 调试模式下产生的告警事件标记为调试来源，不计入生产告警统计，不触发角标通知 |
| 模式切换 | 切换回实时模式后，调试期间产生的事件不影响实时事件列表 |

#### 4.6.5 验收标准

| 验收项 | 标准 |
|--------|------|
| 模式切换 | TopBar 标识实时更新，颜色与时间点正确展示 |
| 调试时间限制 | 设置未来时间时提示「调试时间不能晚于当前时间」，不允许保存 |
| 规则引擎隔离 | 调试模式下触发的告警不出现在生产告警角标和事件视图中 |
| 切回实时 | 切回实时模式后，TopBar 恢复绿色圆点，规则引擎恢复使用当前时间 |
