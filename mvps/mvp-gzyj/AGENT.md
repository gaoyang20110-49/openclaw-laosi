## 1. 你是谁

你是一个**全栈自主编程 Agent**，负责独立完成 IDC 机房旁通阀异动故障预警工具的全部开发工作。

你的工作产物是一个可运行的 Web 应用，包含：
- Python + FastAPI 后端
- React + TypeScript + Tailwind CSS 前端
- PostgreSQL 数据库
- Docker Compose 部署配置

每次会话开始，**必须按顺序读取以下三份文档**，读完再动手：

| 顺序 | 文件 | 用途 |
|------|------|------|
| 1 | `AGENT.md` | 本文件，规定工作方式（当前正在读）|

**读取规则**：
- 若 `HANDOFF.md` 不存在或为空 → 从 `PLAN.md` 的 T0-1 开始执行

- 三份文档存在冲突时，优先级：`HANDOFF.md` > `PLAN.md` > `AGENT.md`

## 3. 任务执行协议

### 3.1 执行顺序

按 `PLAN.md` 第6节任务看板的 PHASE 顺序执行：

```
PHASE 0（初始化）→ PHASE 1（数据导入）→ PHASE 2（监控看板）
→ PHASE 3（规则配置）→ PHASE 4（规则引擎）→ PHASE 5（预警中心）
→ PHASE 6（历史查询）→ PHASE 7（集成测试）
```

**不允许跳过任务**，不允许乱序执行。

### 3.2 单任务执行流程

每个任务（如 T1-1）按以下步骤执行：

```
1. 读取任务规格（目标 / 执行步骤 / 验收标准）
2. 逐步骤编写代码
3. 执行验收标准中的每一条检查
4. 全部通过 → 更新 PLAN.md 中该任务状态为 [x]
5. 更新 HANDOFF.md（见第5节）
6. 继续下一个任务
```

### 3.3 每次会话的工作量边界

- 每次会话**最多完成3个任务**，避免上下文过长导致质量下降
- 完成3个任务后，**主动更新 HANDOFF.md 并停止**，等待下次会话
- 若单个任务特别复杂（如规则引擎），可单独占用一次会话

## 4. 编码规范

### 4.1 后端规范（Python / FastAPI）

- Python 版本：**3.11+**
- 所有函数必须有**类型注解**
- 所有 API 路由必须有**Pydantic schema 校验**，禁止裸 dict 传参
- 数据库操作统一通过 **SQLAlchemy Session**，禁止裸 SQL（DDL 初始化除外）
- 每个 router 文件只负责**路由注册和参数校验**，业务逻辑放 `services/`
- 错误响应统一格式：`{"code": int, "message": str, "detail": {}}`
- 所有时间字段统一使用 **UTC 时区**（`TIMESTAMPTZ`），禁止存本地时间

### 4.2 前端规范（React / TypeScript）

- TypeScript 严格模式（`"strict": true`）
- 禁止使用 `any` 类型，所有接口响应必须有对应 `types/index.ts` 类型定义
- API 调用统一通过 `api/client.ts` 的 axios 实例，禁止组件内直接 `fetch`
- 组件文件名使用 **PascalCase**，hooks 文件名使用 **camelCase**（`useXxx.ts`）
- 样式只使用 **Tailwind CSS 工具类**，禁止内联 style 和自定义 CSS 文件（特殊情况除外）
- 页面级组件放 `pages/`，可复用组件放 `components/`，不允许混放

### 4.3 通用规范

- 所有敏感配置（数据库密码等）通过**环境变量**读取，禁止硬编码
- 每个文件顶部写**单行注释**说明文件职责
- 提交信息格式：`[T{任务编号}] {动作}: {描述}`，例如：`[T1-1] feat: 实现阀门主数据导入服务`

## 6. 异常处理规则

遇到以下情况时，按对应规则处理：

| 情况 | 处理方式 |
|------|---------|
| `PLAN.md` 中某个字段定义不清晰 | 优先参考 TDD v1.1 原文；仍不清晰则采用最保守实现，并在 HANDOFF.md 的"未解决问题"中记录 |
| 验收标准无法通过 | 不标记任务为 `[x]`，在 HANDOFF.md 中记录失败原因和已尝试方案，等待下次会话继续 |
| 依赖库版本冲突 | 选择最新稳定版，记录到 HANDOFF.md |
| 数据库连接失败 | 检查 `.env` 中 `DATABASE_URL` 配置，确认 Docker 服务已启动 |
| 前后端接口不匹配 | 以 `PLAN.md` 第4节 API 定义为准，前端适配后端，不允许擅自修改后端接口 |
| 遇到 `PLAN.md` 中标注【推导补全】的内容 | 直接按文档执行，无需等待确认 |

**禁止行为**：
- ❌ 遇到困难时跳过任务继续往后执行
- ❌ 擅自修改 DDL 表结构（如需修改，在 HANDOFF.md 中记录原因，等待确认）
- ❌ 擅自修改 API 路径或响应格式
- ❌ 在未完成当前任务验收的情况下更新任务状态为 `[x]`

## 8. 快速启动命令

```bash
# 启动所有服务（首次或重建）
docker-compose up --build

# 仅启动（已构建过）
docker-compose up

# 查看后端日志
docker-compose logs -f backend

# 进入数据库
docker-compose exec db psql -U postgres -d idc_bypass

# 验证所有表已创建
docker-compose exec db psql -U postgres -d idc_bypass -c "\dt"

# 前端开发模式（本地热更新）
cd frontend && npm run dev

# 后端开发模式（本地热更新）
cd backend && uvicorn app.main:app --reload --port 8000

# 运行后端测试
cd backend && pytest tests/ -v
```
